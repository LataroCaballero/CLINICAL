<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cliente HTTP autenticado -> `whatsapp.controller.ts:126, 150, 194, 229` | Staff dispara envíos sobre un `pacienteId`/`mensajeId` que provee el cliente |
| backend -> API de Meta (WhatsApp Cloud API) | Request saliente con credenciales desencriptadas del profesional; el guard es la compuerta que debe fallar cerrado antes de este borde |
| service -> cola BullMQ -> processor | El payload cruza a un worker asíncrono donde una excepción ya no llega al usuario |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-10 | Tampering | payload del job encolado (`telefono`) | mitigate | `requireTelefonoParaEnvio()` corre antes de `queue.add` en los 4 paths y devuelve un `string` trimmeado; el processor, que declara `telefono: string` y hace `telefono.replace(/\D/g, '')`, nunca recibe `null` |
| T-67-11 | Information Disclosure | mensaje de error del guard | mitigate | String constante en español, sin interpolación: no expone `pacienteId`, `profesionalId`, `phoneNumberId`, `accessToken`, nombre del paciente ni stack trace. Criterio de aceptación automatizado: el string del guard no contiene `${` |
| T-67-12 | Denial of Service | reintentos y jobs que fallan dentro del worker | mitigate | Al fallar cerrado en el request en vez de encolar, se evitan los 3 `attempts` con backoff exponencial contra Meta por cada envío imposible |
| T-67-13 | Information Disclosure | enumeración de mensajes ajenos vía `retryMessage` | mitigate | El guard de teléfono se coloca DESPUÉS del check de ownership, de modo que un `mensajeId` de otro profesional siga devolviendo `NotFoundException('Mensaje no encontrado')` y no un 400 que revelaría existencia |
| T-67-14 | Repudiation | estado de `MensajeWhatsApp` tras un reintento fallido | mitigate | El guard precede al `update({ estado: 'PENDIENTE', errorMsg: null })`, preservando el `errorMsg` original del fallo previo en vez de pisarlo |
| T-67-15 | Spoofing | fallback a `telefonoAlternativo` como canal | accept | D-04: no se implementa fallback; enviar a un número no consentido para ese canal cambiaría la semántica de envío y roza ENVIO-F02, que está diferido |
| T-67-SC | Tampering | npm/pip/cargo installs | accept | Este plan no instala ni actualiza dependencias. Si apareciera la necesidad, detener y correr el Package Legitimacy Gate antes de continuar |
